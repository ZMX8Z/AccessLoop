复制下面整段到本包开发会话，按本包 [README](README.md) 的交付边界执行。权威文档只在 [authority](../../authority/README.md) 维护。

~~~text
你负责 AccessLoop 工作包 B：上报、报告与管理交互前端，必须完成 P0 和 P1。

开始前按顺序阅读：
1. 根目录 AGENTS.md 和 README.md；
2. docs/authority/README.md：权威资料入口与优先级；
3. docs/authority/PROJECT.md：已确认范围与业务规则；
4. docs/authority/API_CONTRACTS.md：HTTP字段、状态、权限、版本与幂等；
5. docs/authority/COLLABORATION.md：分支预检、目录所有权、内部交接、同步与阶段PR；
6. docs/authority/ACCEPTANCE.md：阶段/整包验收规则、证据与追踪表；
7. 按本包任务查阅 docs/authority/AccessLoop_需求文档_v1.0.md 和 docs/authority/AccessLoop_技术文档_v1.0.md 的相关章节；需要选型依据时查看同目录选型调研；
8. docs/work-packages/b-frontend-reports/README.md、本包交接 docs/handoffs/wp-b.md（如已存在）。

公共约束、接口字段与分支详细规则以以上 authority 文件为唯一维护处；本提示词保留本包业务任务。实现 Schema、文档、fixture 与调用方同步要求按 API_CONTRACTS 执行。

分支与交付先按 docs/authority/COLLABORATION.md 执行：完成当前目录/分支/工作树/归属预检及安全同步，在本包固定分支 codex/b-frontend-reports 上开发；需新建时从 dev 创建，持续同步 dev，PR base 为 dev。记录同步后的 base 与交付 head 提交。使用独立 clone/worktree；复用已归属本包的分支/工作目录，不在同一目录并发切换分支；禁止直接在 dev/main 开发。子 agent 如需分支，按 COLLABORATION 的父包前缀规则执行并先集成回本包分支。

公众主流程、导出模板和后台组件可按可评审阶段交付 PR 到 dev；向 C 提供组件注册说明，并完成真实挂载后再宣称管理功能完成。

交付时按 COLLABORATION 完成检查、交接和 PR，PR base 必须为 dev；若可用工具要求附加 PR，则用相应工具附加实际创建的 PR。将技术验收通过的阶段 PR 交给 D，由 D 依 COLLABORATION 串行合并到 dev；最终所有包都需进入 dev。用户已授权最终集成，常规阶段合并无需重复询问；只有平台保护实际要求人工审批时才报告具体阻塞。

这是直接开发任务，可以用子 agent 分别处理公众流程和后台自定义组件；主 agent 负责集成、自检与交付。完成 P0 后继续 P1，不停留在原型或未挂载组件。

先检查已有代码和交接，保留其他成员改动；沿用 A 的 Stitch 视觉、地图选择/预览组件和公共请求工具，在真实 Payload Admin 中完成管理交互。

P0 子任务：
1. 完成照片选择、上传和分析；调用前取得用户明确选择并说明外部识别服务。展示后端 aiStatus、证据和不确定项。
2. 实现事实字段、观察时间、位置和类别；AI 原始建议与用户修正分开。换照片后失效旧分析，迟到响应不能覆盖新照片或用户编辑。
3. 保存报告并返回编号；复用 A 的路线片段/预设通道选择组件，自动请求 avoidance-preview。只有最终明确确认才启用。
4. 确认携带报告版本、观察时间、通道、同意及预览摘要；冲突保留编辑并重新预览确认。AI不确定/失败时可人工填报，但仍需明确确认。
5. 完成本人列表/详情、个人启停、续期/重新确认、过期及确认失效展示。
6. 完成复制和打印，向 C 提供无浏览器依赖的纯展示模板。用户/AI描述安全转义，状态与影响范围准确。

P1 子任务：
7. 公众报告使用脱敏 DTO，展示公共核实来源、时间、有效期、纠错/驳回/解除状态；个人停用不显示为公共解除。
8. 使用 Payload 原生列表、字段和布局，补齐证据与地图预览：私有照片、原始AI、用户修改、不确定项、公共几何。
9. 完成核实/重新核实、纠错、驳回、解除、重开动作表单，按服务端契约收集独立证据、理由、范围和有效期，处理版本冲突并保留输入；不能用任意 status 编辑替代命令。
10. 补齐审计展示，至少可见操作者、动作、理由、时间和版本，保持只读。
11. 完成当前区域的 bbox、预设通道、缓冲参数和演示标识表单，展示服务端校验/配置冲突。仅运营者可操作，权限由 C 服务端判定。
12. 完成最近24小时 ORS/AI 调用数、等待、错误和缓存命中简单摘要，数据来自受保护接口，区分无数据与读取失败。
13. 向 C 提供后台组件导出和注册说明，并与 C 一起确认已正式挂入 /admin。不能仅把组件文件存在仓库就宣称P1完成。

边界：
- A 维护公共样式和地图；你维护上报/报告功能及 src/components/admin 自定义组件；C 维护 Payload 配置/挂载、鉴权和业务命令；D 维护统计/地理查询服务。
- 管理登录复用 Payload。公众报告不复用完整管理详情，不自动公开原图。
- 共享依赖与lockfile交 D 合并。

执行与交付：
- 服务未就绪时按契约做明确标识的 fixture，继续开发；最终替换并真实联调。缺管理账号时请求受控测试账号，不绕过认证。
- 只做本包静态检查、主流程和必要错误回归；人工验收不承担API、数据库或日志检查。
- 提交 docs/handoffs/wp-b.md：P0/P1清单、页面/后台入口、模板和组件交接、实际检查证据、阻塞项、120秒演示稿及人工点击脚本。
~~~
