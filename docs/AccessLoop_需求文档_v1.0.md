# AccessLoop 需求文档

无障碍地点查询与临时障碍绕行的黑客松 MVP

版本 v1.0 评审版    日期 2026年10月17日

AccessLoop 帮助轮椅使用者在有限区域内查询地点、规划路线、报告临时障碍，并在障碍核实后获取绕行结果。比赛版本应证明一个完整流程：发现障碍，核实影响范围，重新规划，整理可提交的维修报告。本文供产品、开发、测试与演示人员统一范围和验收口径。

## 1 项目目标与约束

### 1.1 已明确的背景

分享对话涉及多个候选项目，后续讨论持续聚焦 AccessLoop，并明确已取得 openrouteservice 接口访问能力。本需求以该项目为对象，采用对话后段修正后的外部路线服务方案。此前的自建路网与 Dijkstra 方案不作为比赛版本的开发前提。[S1]

| 类型 | 基线 | 确认程度 |
| --- | --- | --- |
| 开发条件 | 24–48 小时，3–4 人团队 | 对话中用户明确 |
| 部署与评审 | 使用 Zenith 部署，面向大众评审团 | 对话中用户明确 |
| 已有资源 | 已取得 ORS 接口；存在频率和每日额度限制 | 用户明确取得接口，额度由对话转述截图 |
| 产品方向 | 地点查询、轮椅路线、临时障碍上报与绕行 | 按后续讨论整理 |
| 交付范围 | 一个小区域的移动端 Web 应用 | 本版建议，区域待选择 |
| 技术实现 | Next.js 全栈，后端代理 ORS，人工审核 | 建议方案，见技术文档 |

### 1.2 产品价值与成功标准

项目价值是让一条障碍报告进入路线决策。地图上的障碍图标、图片分类结果和路线变化必须由真实数据关联。路线仍受地图覆盖、时效与现实环境限制；“已核实”仅说明报告经过人工核实，不代表整条路线经过专业无障碍认证。

- 闭环成功：相同起终点、相同轮椅参数下，核实障碍后返回避开该区域的路线，或明确说明没有符合条件的路线。

- 部署成功：Zenith 上可访问，服务重启后报告和图片仍存在，密钥不出现在浏览器请求或前端资源中。

- 演示成功：在约 120 秒内展示规划、上报、核实、绕行和报告；至少保留三个可复现的测试场景。

- 体验目标：邀请至少 3 位目标或相近使用者试用，记录完成情况和阻塞点。人数为本版建议目标，不能替代轮椅使用者的实际验证。

## 2 目标用户与使用场景

| 角色 | 主要任务 | 权限边界 |
| --- | --- | --- |
| 出行者 | 查看地点、设置起终点和需求、规划或重算路线 | 只读公开内容；经匿名会话可提交报告 |
| 障碍上报者 | 上传照片、确认位置、修正类别和描述 | 提交后进入待核实；不能自行生效或解除障碍 |
| 核实管理员 | 核实照片和位置，调整受影响区域，确认或解除障碍 | 服务端鉴权；变更留存记录 |
| 部署运营者 | 配置实例、区域、服务密钥、演示数据和使用预算 | 配置权限与普通公众隔离 |

首要场景是轮椅使用者在校园或邻近街区从入口前往图书馆，途中某段通道被施工围挡占用。推婴儿车者和其他行动不便者可作为后续用户；wheelchair 路线模式并不自动等同于所有人群的个性化适配。校园仅为建议场景，具体区域需团队选择并走访。

## 3 版本范围与优先级

P0 为 24 小时核心闭环，P1 为 48 小时增强，P2 为后续迭代。本版将早期方案中的 AI 识别由硬性启动条件调整为增强项，以便没有 AI 密钥或识别失败时仍能完成上报。这是范围建议，团队可在开工前确认；图片上传、人工核实和真实绕行仍属于 P0。

| 需求 | 优先级 | 交付边界 |
| --- | --- | --- |
| 地图与地点 | P0 | 一个配置区域；展示来源、类别和无障碍状态 |
| 起终点与轮椅路线 | P0 | 地图选点或预设地点；一次显式操作触发计算 |
| 照片与人工上报 | P0 | JPG/PNG 照片、点位、类别、描述、拍摄时间 |
| 管理员核实 | P0 | 待核实、已核实、已解决、已驳回；确认避让多边形 |
| 障碍生效与绕行 | P0 | 有效障碍加入 ORS 请求；失效缓存不能返回旧路线 |
| 报告整理 | P0 | 可复制文字和可打印报告页，供用户人工提交 |
| 配额与异常处理 | P0 | 服务端预算、等待提示、无路可走与外部失败区分 |
| AI 照片分类 | P1 | 建议类别与描述，人工确认；失败可手动继续 |
| 地点文字搜索 | P1 | 地址搜索；没有接入时保留地图和预设地点选点 |
| 社区确认与精细个性化 | P2 | 投票、声誉、个人资料、推送和更多通行参数 |
| 全城与自动市政集成 | P2 | 扩大覆盖、实时公共设施接入、获授权后的提交接口 |

比赛范围不包含自建全球路由引擎、室内导航、语音逐向导航、完整账号体系、多租户计费、自动确定道路尺寸或自动判定安全。等时圈接口不是核心闭环依赖。商业定价和付费实例数量单独验证，不写成既有成果。

## 4 核心流程与业务规则

### 4.1 规划与报告流程

打开区域地图 → 选择起点和终点 → 选择通行参数 → 规划路线 → 查看距离、估算时长、数据来源和障碍提示。出行者可在当前位置或手工选点上传照片，填写或修正类别与描述，确认位置后提交。提交成功后显示报告编号和“待核实”，不自动改变全局避让区域。

### 4.2 核实与重新规划流程

管理员查看证据 → 核对受影响通道 → 绘制或调整多边形 → 设置有效期与理由 → 确认障碍。确认后系统更新障碍版本，提示已有路线可能过时。用户点击重算，后台将有效避让区域发送给 ORS，返回新路线或“当前条件下未找到路线”。报告可在任何状态生成，但必须展示当时状态。

### 4.3 状态与生效规则

| 状态 | 含义 | 地图与路线行为 |
| --- | --- | --- |
| pending 待核实 | 上报已保存，位置或范围尚未确认 | 显示待核实提示；不自动进入强制避让 |
| verified 已核实 | 管理员确认且具有有效几何与有效期 | 有效期内纳入避让；标记核实时间 |
| resolved 已解决 | 管理员确认障碍已解除 | 停止避让并更新版本；保留历史 |
| rejected 已驳回 | 证据不足、位置错误或重复等 | 不参与避让；保留理由 |
| 核实已过期 | 由 verified 与有效期推导的展示状态 | 不作为当前核实障碍；显示信息过时，等待复核 |

只允许管理员将 pending 改为 verified 或 rejected，将 verified 改为 resolved，或通过重新核实延长有效期。重新打开已解决或驳回的报告时先回到 pending。核实过期不等于障碍已经消失，不显示“已恢复通行”。有效期建议默认 24 小时，可由管理员调整；该时长为待确认运营规则。

- 位置与影响范围分开：上报点表示发现位置，避让多边形表示核实的受影响区域，照片中的位置不能由 AI 直接推断。

- 未核实或未知不能显示为安全。地点可进入不能推导到达它的道路都可通行；普通厕所不能推导为无障碍厕所。

- 待核实障碍接近当前路线时给出文字提醒；本版不靠一条未经核实的公开报告自动封路。

- 多人重复提交同一位置时可标为疑似重复供管理员处理，比赛版不自动合并或自动提高可信度。

## 5 功能需求与验收口径

### 5.1 地图与地点

FR01 区域地图。默认显示配置的演示区域，提供图例和列表视图。地图可定位、缩放和选点；位置权限被拒绝时可手工选起点。验收：手机在不授权定位的情况下仍能完成规划，地图标记与列表一一对应。

FR02 地点状态。显示地点名称、类别、坐标、来源、更新时间，以及可进入、部分可进入、不可进入或未知状态。字段缺失时显示未知，不通过类别或名称推断。验收：包含明确 yes、limited、no 和缺失标签的四条样例均正确展示，分类标签保留原始来源。

FR03 起终点与参数。P0 支持地图选点与预设地点，显示当前 wheelchair 模式和实际使用的限制参数。坡度用百分比，路缘高度和宽度用米；示例数值不是医学建议。验收：起终点可交换、可更换，坐标超出区域会给出可执行提示。

### 5.2 路线与障碍处理

FR04 路线结果。显示路线、距离、估算时长、计算时间、障碍版本及数据限制；明确为基于当前数据的候选路线。只有点击规划、重算或修改确认后的参数才发起计算。验收：拖动地图、切换面板、重绘页面不增加 Directions 调用。

FR05 上报障碍。必须提供照片、地图位置、类别和描述；拍摄时间默认当前但可修改。建议类别为施工阻断、台阶或高路缘、路面损坏、通道占用、其他，支持“不确定”。验收：上传无效文件、位置缺失和描述缺失均不能提交；正常提交持久化并返回编号。

FR06 核实管理。管理员可查看原图，调整类别和位置，确认实际影响区域、有效期和理由；一般用户不能核实、驳回或解除。验收：绕过界面直接调用接口仍无法越权；两名管理员并发修改时不能无提示覆盖。

FR07 障碍绕行。后台纳入本区域全部当前有效已核实障碍。规划前后保持起终点和通行参数一致，以便比较避让效果。验收：新路线不穿越有效避让区域；若返回路线越出演示区域，提示超出覆盖范围；替代路线不存在时返回无可用路线，不能移除障碍或放宽参数来制造成功。

FR08 版本与重算提示。障碍新建、核实、范围修正和解除后使相关结果过时。正在显示旧结果的页面应在 10 秒内获知变更并提示重算。验收：另一个浏览器核实障碍后，原页面不会继续把旧路线标为最新；排队中的旧请求也不能覆盖新结果。

### 5.3 照片识别与报告

FR09 AI 辅助识别。P1 根据照片生成候选类别、描述和不确定点，用户可全部修改。对模糊照片可返回无法判断；不凭照片生成通行宽度、坡度或可通行结论。验收：AI 超时、无密钥或返回无效结构时，表单仍可人工完成并提交。

FR10 报告页。包含编号、照片、位置、类别、事实描述、发现与核实时间、当前状态及待用户完成的提交步骤；提供文字复制与打印。验收：打印页内容完整，未核实报告有明确状态，界面不出现未经实际完成的“已提交市政”或“已修复”。

FR11 异常与等待。分别显示参数错误、定位失败、无路线、排队、配额耗尽和外部服务故障。重试保留表单输入，不把 403 全部解释成额度耗尽。验收：每种错误有独立测试样例；失败不产生未经核实的替代路线。

### 5.4 部署和演示模式

FR12 访问与隔离。公众扫码打开移动端体验；演示报告和真实报告使用独立实例或隔离区域，并持续标识演示数据。管理员使用受保护的登录入口；不能靠前端角色切换获得权限。验收：公开二维码不能直接进入管理员会话。

FR13 数据持久化。图片和报告不写入临时应用目录。验收：创建带照片报告后重启部署，记录、图片和核实状态均可重新读取。

FR14 请求预算。ORS 调用由服务端统一发出，按服务分别设限，并为同一密钥的所有实例共享预算。验收：超过预算时显示等待或稍后重试；相同请求复用结果，障碍版本改变后不会复用旧结果。

## 6 页面与交互要求

| 页面 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 地图首页 | 地点、障碍、起终点、路线摘要和图例 | 规划、手工选点、切换列表、重算 |
| 上报页面 | 照片、发现时间、位置、类别、描述 | 上传预览，修正 AI 建议，提交后显示编号 |
| 报告详情 | 证据、状态、核实时间、来源和有效期 | 复制报告文字、打印、返回地图 |
| 管理员页面 | 待核实列表、地图范围、修改历史 | 确认范围、核实、驳回、解除与重新核实 |
| 部署说明入口 | 区域范围、数据源、使用限制、配置指引 | 进入演示或查看部署步骤 |

移动端主操作始终可见，地图不能成为唯一入口；提供可聚焦的表单、键盘操作和文本结果。颜色之外同时使用图标与文字表示状态。界面语言建议英文优先以配合现场观众，保留中文扩展空间；最终语言待团队确认。

## 7 非功能需求

以下数字均为建议验收目标，不是已测得结果或供应商承诺。测试环境记录手机型号、网络、区域大小和账号预算；超过第三方配额的请求应按等待规则处理，不纳入正常请求耗时。

| 编号 | 要求 | 可测目标 |
| --- | --- | --- |
| NFR01 | 移动端可用 | 支持 360 像素宽度；无横向溢出；拒绝定位仍可用 |
| NFR02 | 操作反馈 | 点击后 300 毫秒内显示加载或排队状态 |
| NFR03 | 路线响应 | 30 次低负载测试中，未排队路线请求 P95 小于 8 秒；缓存命中小于 1 秒 |
| NFR04 | 状态传播 | 障碍状态改变后 10 秒内提醒现有客户端 |
| NFR05 | 一致性 | 同起终点和参数使用一致障碍快照；不返回已知过时的成功结果 |
| NFR06 | 权限与数据 | 密钥只在服务端；审核鉴权；图片不公开暴露原始元数据 |
| NFR07 | 容量目标 | 演示支持 20 个浏览会话；路线调用仍受统一分钟预算控制 |
| NFR08 | 可访问交互 | 表单有标签；焦点可见；文字可替代颜色；地图信息有列表表达 |
| NFR09 | 维护与恢复 | 部署说明可复现；完成一次重启验证和数据备份恢复演练 |

## 8 验收场景与完成定义

| 用例 | 触发条件 | 通过标准 |
| --- | --- | --- |
| AC01 正常规划 | 无有效障碍，固定两点和参数 | 得到有效路线；显示来源、时间和限制 |
| AC02 待核实 | 同一路线附近新增 pending 报告 | 可见提醒；未被擅自变为已核实封路 |
| AC03 障碍绕行 | 核实覆盖原路径的合理多边形 | 新路线不穿越区域，或明确无路线 |
| AC04 障碍解除 | 已核实报告被确认解决 | 版本更新；新请求不再使用旧避让区域 |
| AC05 无可用路线 | 全部替代通道均不满足条件 | 无可用路线；不暗中移除限制 |
| AC06 上游异常 | 模拟 429、配额 403、鉴权 403、超时 | 错误准确，有限重试，不出现请求风暴 |
| AC07 权限与并发 | 访客审核；两个管理员同时改同一报告 | 访客拒绝；过期版本返回冲突 |
| AC08 缓存竞争 | 路由计算时核实障碍；客户端仍有旧请求 | 旧结果不标为当前；不覆盖较新请求 |
| AC09 持久化 | 创建图片报告并重启应用 | 记录、图片、状态可读 |
| AC10 降级与报告 | AI 不可用；地点字段缺失；打印报告 | 可人工提交；未知保持未知；报告完整 |

完成定义：P0 功能已部署到 Zenith；上述适用验收通过；实际测试证据与已知问题有记录；README 含启动、配置、区域、数据来源和部署方法；公开页面不暴露管理权限；至少一次完整彩排。AI 未接入时在交付说明中列明 P1 状态，不能用预存结果冒充实时识别。

## 9 团队分工与交付节奏

| 负责人 | 主要工作 | 可检查的交付 |
| --- | --- | --- |
| A 前端与体验 | 地图、选点、路线比较、上报和报告页 | 手机上完整操作一次闭环 |
| B 路由与地理处理 | ORS 集成、避让几何、缓存和配额 | 固定两点在障碍生效后真实绕行 |
| C 数据与后端 | 上传存储、报告接口、审核权限、可选 AI | 报告可核实、可追踪、重启不丢失 |
| D 部署与验证 | Zenith、端到端测试、用户反馈和 Demo | 在线地址、测试结果、120 秒演示 |

三人团队建议 A 兼演示，B 兼路由测试，C 先完成部署再接 AI，三人共同招募试用者。以实际可用时间排期，表中时间从项目开工计算。

| 阶段 | 24 小时版 | 48 小时版 | 退出条件 |
| --- | --- | --- | --- |
| 部署和验证 | 0–2h | 0–4h | 空壳上线；取得真实轮椅路线；验证避让请求 |
| 骨架集成 | 2–8h | 4–14h | 地图、报告保存、上传和审核接口互通 |
| 核心闭环 | 8–14h | 14–24h | 核实后绕行或明确无路线；缓存更新正确 |
| 体验与增强 | 14–19h | 24–36h | 报告页、限流和错误提示；48h 加 AI 与搜索 |
| 冻结与彩排 | 19–24h | 36–48h | 权限、重启、手机测试，真实反馈，备用录像 |

120 秒演示建议：0–20 秒说明通道受阻问题并显示原路线；20–45 秒提交照片和位置；45–65 秒由管理员核实；65–95 秒重算并比较；95–110 秒展示报告；110–120 秒说明使用范围与部署入口。固定起终点和参数，只改变障碍条件。

## 10 风险与待确认事项

| 事项 | 处理方式 | 确认时点 |
| --- | --- | --- |
| 演示区域与覆盖 | 选定小范围，实测路线及备选通道，走访关键路段 | 开工前 2 小时 |
| Zenith 运行条件 | 核实 manifest、端口、密钥、外网、资源和持久化 | 首次部署时 |
| 配额与多实例 | 复查当前账号；确认是否一把密钥被多人或多实例共用 | ORS 集成前 |
| 地点数据不足 | 优先测试 HeiGIT POI，缺少字段再评估 Overpass 等 | 地图集成前 |
| 商业与数据授权 | 按数据源许可和平台条件确认再发布商业实例 | 对外售卖前 |
| 核实责任与有效期 | 指定管理员，确认 24h 建议有效期及重新核实流程 | 公开体验前 |
| 语言与 AI 优先级 | 确认界面语言，24h 是否人工优先，48h 是否必须 AI | 范围冻结前 |
| 图片与数据保留 | 建议照片及报告保留 30 天，可由管理员删除；时长需确认 | 公开收集前 |
| 官方提交入口 | 确认演示区域对应管理机构和链接，用户自行提交 | 报告页上线前 |
| 评审规则 | 以现场规则确认发布审核、付费实例或人气奖是否计分 | Pitch 定稿前 |

不能把 API 可用、当地路网完整、路线实际可通行、商业授权通过和项目已上线混为一个结论。每项分别保留实测或确认记录；演示数据和历史录屏在页面或讲解中明确标识。
