# AccessLoop 页面架构（基于 Stitch）

版本：v0.1 · 2026-10-17
用途：先确认页面层级与导航关系，再据此重构前端。本文件不是代码目录设计，也不代表功能已经完成。

## 1. 架构原则

AccessLoop 是以 **三个主要功能 Tab** 组织的移动端应用：

**Route｜Report｜My Reports**

三个 Tab 是并列的一层入口。每个入口拥有自己的页面或流程；下属页面不能全部堆在 Route 首页。

- **Route**：查看地图、设置行程、查看路线、进入行程页面。
- **Report**：拍照或上传照片、查看 AI 分析并确认、完成上报。
- **My Reports**：查看自己上报的记录、筛选状态、进入具体报告。

当前实现中的大标题介绍区、左右并列规划控制台、首页集中展示所有报告状态及组件演示，不作为下一版页面架构。下一版按 Stitch 的「顶部栏 + 主内容 + 底部 Tab Bar」组织。

## 2. 总体页面树

```text
AccessLoop
│
├── Tab 1：Route（默认入口）
│   │
│   ├── R1 路线首页 / 路线预览
│   │   ├── 地图主视图
│   │   ├── 地点搜索与起终点设置【页内面板】
│   │   ├── 地图图层、图例、地点列表【页内面板】
│   │   ├── 当前障碍 / 绕行说明【卡片；Inspect 打开详情】
│   │   └── Start Journey 按钮【位于 R1，点击切换至 R2】
│   │
│   └── R2 行程页面【由 R1 内的 Start Journey 按钮进入】
│       ├── 保留当前路线地图与行程摘要
│       ├── 地图下方展示路线节点 / 路段列表
│       └── 暂停、上报障碍、结束行程等动作
│
│
├── Tab 2：Report
│   │
│   └── 新建障碍报告（三步顺序流程）
│       ├── P1 Photo：拍照 / 上传证据
│       ├── P2 AI Scan：分析结果与用户确认
│       │   ├── 照片及分析结果
│       │   ├── 位置选择【页内面板】
│       │   └── 修正类别 / 描述 / 观察时间
│       │
│       └── P3 Submitted：上报成功
│           ├── 报告编号
│           └── Return to Route
│
└── Tab 3：My Reports
    │
    ├── M1 我的报告列表
    │   ├── All
    │   ├── Active Detour
    │   └──Resolved
    │
    │
    └── M2 我的报告详情【补充设计，Stitch 未提供独立画面】
        ├── 报告事实、照片、分析与确认状态
        ├── 个人避让状态、来源与有效期
        └── 查看相关路线 / 停用或重新确认避让 / 复制与打印
```

说明：R3、M2 是为承接 Inspect 和列表项点击而补出的下级页面，并非现有 Stitch 已绘制页面。搜索、参数、位置、通道及预览的具体面板布局也需后续细化，但不增加第四个主 Tab。

| Route | R2 行程页面 | `route_active_journey_guidance` | 已有画面；当前行程、路线节点及结束行程操作 |
| Report | P1 照片 | `report_stage_1_upload_evidence` | 已有画面；Photo → AI Scan → Submitted 流程的第一步 |
| Report | P2 分析与确认 | `report_stage_2_ai_scan_confirm` | 已有画面；第二步；可编辑并返回修改照片 |
| Report | P3 成功 | `report_stage_3_successfully_reported` | 已有画面；成功编号、返回路线、底部 Tab Bar |

## 4. Tab 1：Route

### R1 路线首页 / 路线预览

**页面角色**：用户打开应用后的默认页面，也是规划与重算路线的主要位置。

由上到下：

1. 顶部品牌栏：AccessLoop、Demo 标识（仅演示区域）、设置入口。
2. 地图区：顶部搜索 / 参数入口；地图上的定位、图层控制。
3. 底部路线摘要：起点 → 终点、距离、估计时长、适用指标。
4. 主按钮：Start Journey（已有路线时）。尚未规划时使用设置起终点 / Plan Route 的对应状态。
5. 当前绕行提示：关联的障碍、绕行原因、Inspect 入口。
6. 全局底部 Tab Bar：Route 高亮。

**页内状态**：未选点、选点中、规划中、路线可用、路线过时、无路线、服务错误。它们属于 R1 的不同状态，不各建一个导航页面。

**下级操作**：

- 搜索、起终点选择、交换、参数设置 → 在 R1 内通过面板完成。
- Plan / Recalculate → 更新 R1 的地图和摘要。
- **R1 内的 Start Journey 按钮** → 切换到 R2 行程页面，保留地图并显示路线节点信息。
- Inspect → R3。
- 点击 Report Tab → P1。

### R2 行程页面

**页面角色**：用户点击 **R1 页面内的 Start Journey 按钮** 后，切换进入 R2。R2 保留当前路线地图，并在地图下方展示路线节点 / 路段信息；仍属于 Route Tab。

由上到下：

1. 顶部栏：返回按钮、行程标题。
2. 保留地图：继续展示 R1 已选行程的路线与起终点，并显示当前行程摘要。
3. 地图下方的路线节点 / 路段列表：起点、当前节点、后续路段、终点。地图与节点信息在同一页面展示。
4. 行程操作区：Stitch 中有 Audio、Detour、End Journey 等按钮。
5. 底部 Tab Bar：仍属于 Route，Route 高亮。

**导航关系**：

- 返回 → R1，保留起终点、参数与路线。
- 上报障碍 → P1，携带当前路线作为可选上下文。
- End Journey → 退出行程状态，回 R1。

**能力边界**：保留 Stitch 的页面层级，但不能仅凭静态画面宣称已有实时定位跟踪、语音导航、经过节点判定或可靠安全等级。具体动作必须按已实现能力启用。

### R3 当前障碍详情（补充页）

从 R1 的 Inspect 进入。展示当前障碍的公开信息，或当前用户有权读取的本人信息；返回到原路线页面。它不等同于 My Reports 的完整本人报告详情，其他人的私有照片与分析不在这里展示。

## 5. Tab 2：Report

**入口原则**：点击 Report 进入新建上报流程。用户正在编辑时保留当前草稿；不能每次切换 Tab 都自动丢弃。

### P1 Photo：拍照 / 上传证据

由上到下：

1. 顶部栏：返回按钮、New Barrier Report。
2. 三步进度条：Photo → AI Scan → Submitted。
3. 拍照 / 从相册上传。
4. 已选照片预览及替换 / 删除操作。
5. 位置摘要与修正入口。
6. 主按钮：Confirm & Analyze Photo。
7. 次操作：取消并返回来源页面。

**下一步**：用户明确同意分析并提交照片，进入 P2 的分析中状态；成功或失败均在 P2 呈现，不虚构成功结果。

### P2 AI Scan：分析结果与用户确认

由上到下：

1. 相同顶部栏及步骤条，第二步高亮。
2. 照片与分析状态：已完成、不确定或不可用。
3. 障碍类别、事实描述与可编辑信息。
4. 观察时间、位置确认。
5. 受影响通道选择：当前路线片段 / 预设通道。
6. 后端返回的避让范围预览。
7. 是否为自己临时避让的明确确认。
8. 主按钮：Submit Report；次操作：Edit Photo / Rescan。

**导航关系**：

- 返回 / Edit Photo → P1，保留草稿；更换照片后使旧分析、旧预览和相关确认失效。
- 提交失败 → 留在 P2，保留输入并显示具体错误。
- 提交成功 → P3。

通道选择和范围预览属于这个上报流程，不单独放在 Route 首页作为面向用户的组件演示。

### P3 Submitted：上报成功

由上到下：

1. 顶部栏与完成状态的进度条。
2. 成功图标和确认文案。
3. 真实报告编号与实际生效范围。
4. 主按钮：Return to Route。
5. 底部 Tab Bar：Report 高亮。

**导航关系**：

- Return to Route → R1，保留原行程；若避让条件变化，提示用户显式重算。
- My Reports Tab → M1，可见新创建的本人报告。
- 再次开始上报 → 新建 P1 草稿，不重复提交上一份报告。

## 6. Tab 3：My Reports

### M1 我的报告列表

由上到下：

1. 顶部品牌栏：AccessLoop、Demo 标识（适用时）。
2. 标题 My Reports 与数量。
3. 筛选条：All / Active Detour / Resolved。
4. 报告列表：名称、编号、地点、状态、简要说明与有效期。
5. 底部 Tab Bar：My Reports 高亮。

**状态**：加载、空列表、筛选无结果、加载失败。状态属于列表页，不扩充顶层导航。

**点击报告项** → M2。

### M2 我的报告详情（补充页）

展示该用户有权读取的报告事实、照片、分析状态、用户确认、个人 / 公共影响及有效期。相关操作在详情中完成，避免把所有报告操作堆在列表或路线首页。

- 返回 → M1，并保留筛选状态。
- 查看相关路线 → Route；需要重新规划时由用户明确触发。
- 停用 / 重新确认个人避让 → 使用对应业务流程，不能直接切换公共核实状态。
- 复制 / 打印 → 该报告的输出操作，不新增主 Tab。

## 7. Tab Bar 与返回规则

| 页面 | Tab 归属 | 底部 Tab Bar | 返回目标 |
| --- | --- | --- | --- |
| R1 路线预览 | Route | 显示；Route 高亮 | 默认入口 |
| R2 行程页面 | Route | 显示；Route 高亮，遵循 Stitch | R1 |
| R3 障碍详情 | Route | 建议显示；Route 高亮，待补充画面 | 原路线页面 |
| P1 上传照片 | Report | Stitch 原稿未显示；采用专注步骤页 | 发起上报的页面 |
| P2 分析确认 | Report | Stitch 原稿未显示；采用专注步骤页 | P1 |
| P3 上报成功 | Report | 显示；Report 高亮 | Return to Route → R1 |
| M1 我的报告列表 | My Reports | 显示；My Reports 高亮 | 切换其他 Tab |
| M2 我的报告详情 | My Reports | 建议显示；My Reports 高亮，待补充画面 | M1 |

- 全局 Tab 切换是功能切换；顶部返回是退出当前下级页面或退回上一步，两者职责不同。
- 从 Route 进入 Report，要记录来源和当前路线引用；从 My Reports 进入 Report，也应保留正确的取消返回目标。
- Tab 切换保留起终点、轮椅参数、合法路线状态及列表筛选；过期结果必须标为过时。
- 草稿保留不等于已经保存报告；成功页只能在服务端确认成功后出现。
- 若用户明确放弃未提交草稿，可提示确认丢弃；普通切换不自动清空。

## 8. 主要操作路径

```text
规划行程：
Route / R1 → 设置起终点和参数 → Plan Route → R1 路线预览
          → 点击 R1 内的 Start Journey → R2（保留地图 + 展示路线节点）→ End Journey → R1

途中发现障碍：
R1 或 R2 → Report / P1 照片 → P2 分析与确认 → P3 成功
         → Return to Route → R1 提示条件变化 → 用户点击 Recalculate

查阅自己的记录：
My Reports / M1 → 筛选或选择报告 → M2 报告详情 → 返回 M1

检查当前路线的障碍：
Route / R1 → Inspect → R3 障碍详情 → 返回 R1
```

## 9. 建议 URL（实现映射，非新增功能）

| 路径 | 页面 |
| --- | --- |
| `/` | 默认进入 Route；可重定向 `/route` |
| `/route` | R1 路线预览 |
| `/route/journey` | R2 行程页面 |
| `/route/barriers/[id]` | R3 当前障碍详情 |
| `/report` | P1 照片 |
| `/report/confirm` | P2 分析与确认 |
| `/report/success/[id]` | P3 成功 |
| `/my-reports` | M1 本人报告列表 |
| `/my-reports/[id]` | M2 本人报告详情 |

直接进入下级 URL 时须检查上下文：没有路线不能假装开始行程，没有照片/草稿不能假装已分析，没有成功提交记录不能展示成功。URL 只标识页面，不授予读取报告的权限。

## 10. 忠于结构，但不照搬不真实的示例文案

以下内容存在于 Stitch 原稿，只作为视觉占位，实施时必须改为真实业务状态：

- AI Dimension Gauge、98% Match、精确照片测宽：不能当作已经实现的可靠测量。
- Logged to Campus Facilities、Crew Dispatched：没有实际提交或派工集成就不能显示为事实。
- High-Assurance Trail、Clear passage：不能把未知或未核实信息包装成安全保证。
- Auto-routed：按项目规则，条件变化提示用户显式重算，不能因轮询自动调用路线服务。
- Audio On、实时节点与到达时间：不在没有实现实时导航时展示虚假运行状态。
- 原稿中的示例坐标、日期、设施和报告编号不代表 UNSW 实测数据。

这些限制调整的是数据和行为真实性，不改变三个 Tab 及其下属页面的组织方式。
