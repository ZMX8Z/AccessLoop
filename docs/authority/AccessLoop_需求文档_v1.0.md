# AccessLoop 需求文档

> 当前权威入口：[文档索引](README.md)。项目决定、字段契约、协作与验收分别由 PROJECT.md、API_CONTRACTS.md、COLLABORATION.md、ACCEPTANCE.md 维护；本文保留所属范围的需求、架构或选型依据。

无障碍地点查询与临时障碍绕行的黑客松 MVP

版本 v1.3 四人协作与 GLM 方案确认版    日期 2026年10月17日

AccessLoop 帮助轮椅使用者在有限区域内查询地点、规划路线、报告临时障碍，并获得临时绕行建议。比赛版本的核心流程为：上传照片，由支持图片输入的大模型返回结构化识别结果，用户确认位置和受影响通道，后端生成个人临时避让区域并重新规划，最后整理可提交的维修报告。管理员不再是每条报告的必经审核环节，负责异常处理、公共报告的额外核实和纠错。本文供产品、开发、测试与演示人员统一范围和验收口径。

## 1 项目目标与约束

### 1.1 已明确的背景

分享对话涉及多个候选项目，后续讨论持续聚焦 AccessLoop，并明确已取得 openrouteservice 接口访问能力。本需求以该项目为对象，采用对话后段修正后的外部路线服务方案。此前的自建路网与 Dijkstra 方案不作为比赛版本的开发前提。[S1]

| 类型 | 基线 | 确认程度 |
| --- | --- | --- |
| 开发条件 | 24–48 小时，4 人团队 | 对话中用户明确 |
| 部署与评审 | 使用 Zenith 部署，面向大众评审团 | 对话中用户明确 |
| 已有资源 | 已取得 ORS 接口；存在频率和每日额度限制 | 用户明确取得接口，额度由对话转述截图 |
| 产品方向 | 地点查询、轮椅路线、临时障碍上报与绕行 | 按后续讨论整理 |
| 交付范围 | 一个小区域的移动端 Web 应用 | 已确认 UNSW Kensington 校园内的小区域，边界待实测 |
| 技术实现 | Next.js + Payload 全栈，PostgreSQL 与阿里云 OSS 私有对象存储；后端代理 ORS，多模态大模型识别与 JSON Schema 输出 | 用户已确认采用 Payload 与阿里云 OSS；接口细节见技术文档 |

后端与管理后台选型已确定为 **Payload**，集成于同一个 Next.js 应用。Payload 提供数据管理、管理员认证、上传适配和 Payload Admin 管理界面；AccessLoop 实现 AI 分析、匿名会话归属、用户确认、个人与公共避让、路线计算和配额规则。采用该方案的依据见[开源后端与后台选型调研](AccessLoop_开源后端与后台选型调研.md)，具体接入设计见[技术文档](AccessLoop_技术文档_v1.0.md)。

照片存储已确定使用 **阿里云 OSS 托管服务与私有 Bucket**，通过服务端校验上传和授权读取；访问密钥不交给浏览器。数据库保存照片标识、归属与对象键，图片文件存入 OSS。具体地域、Bucket、凭据及 Zenith 连通性在首次部署时验证。

### 1.2 产品价值与成功标准

项目价值是让一条障碍报告进入路线决策，并让上报者无需等待管理员即可尝试绕行。地图上的障碍图标、AI 识别结果、用户确认的位置与路线变化必须由真实数据关联。个人临时避让只影响当前会话；影响所有用户的公共障碍另行核实。“AI 已分析”与“已核实”分别展示，均不代表整条路线经过专业无障碍认证。

- 闭环成功：相同起终点、相同轮椅参数下，完成 AI 识别和用户位置及通道确认后，无需管理员操作即可生成个人临时绕行建议，或明确说明没有符合条件的路线；其他会话不受该个人报告影响。

- 部署成功：Zenith 上可访问，服务重启后报告和图片仍存在，密钥不出现在浏览器请求或前端资源中。

- 演示成功：在约 120 秒内展示规划、上报、AI 分析、用户确认、绕行和报告；至少保留三个可复现的测试场景。

- 体验目标：邀请至少 3 位目标或相近使用者试用，记录完成情况和阻塞点。人数为本版建议目标，不能替代轮椅使用者的实际验证。

## 2 目标用户与使用场景

| 角色 | 主要任务 | 权限边界 |
| --- | --- | --- |
| 出行者 | 查看地点、设置起终点和需求、规划或重算路线 | 读取公共数据及本会话个人避让结果 |
| 障碍上报者 | 上传照片、修正 AI 建议、确认位置和受影响通道 | 可启用或停用自己的个人临时避让；不能修改他人报告或直接发布公共障碍 |
| 纠错管理员 | 处理争议、明显错误和公共报告的额外核实，修正或撤销公共障碍 | 不是个人绕行的前置条件；服务端鉴权，变更留存记录 |
| 部署运营者 | 配置实例、区域、服务密钥、演示数据和使用预算 | 配置权限与普通公众隔离 |

首要场景是轮椅使用者在校园或邻近街区从入口前往图书馆，途中某段通道被施工围挡占用。推婴儿车者和其他行动不便者可作为后续用户；wheelchair 路线模式并不自动等同于所有人群的个性化适配。本轮区域已选定 UNSW Kensington 校园，具体小范围、固定起终点和备选通道由 D 实测并交接。

## 3 版本范围与优先级

P0 为 24 小时核心闭环，P1 为 48 小时增强，P2 为后续迭代。AI 图片识别与结构化输出属于 P0，取消管理员逐条必审。用户确认位置和通道后，后端根据规则启用个人临时避让；公共生效仍需要独立证据。AI 不可用时保留人工填报和明确确认后的个人避让备用路径，但未接入实时 AI 不能视为全部 P0 完成。

Payload 数据层、私有上传适配及服务端访问控制纳入 P0 技术基础；面向管理员的公共核实、纠错和解除操作保持 P1。公众通过移动端业务页面使用应用，管理员通过受保护的 `/admin` 入口工作。Payload 自动生成的 CRUD 不得绕过业务规则，也不改变个人绕行无需管理员参与的验收口径。

| 需求 | 优先级 | 交付边界 |
| --- | --- | --- |
| 地图与地点 | P0 | 一个配置区域；展示来源、类别和无障碍状态 |
| 起终点与轮椅路线 | P0 | 地图选点或预设地点；一次显式操作触发计算 |
| 照片与障碍上报 | P0 | JPG/PNG 照片、点位、类别、描述、拍摄时间；AI 建议可修正 |
| 用户确认与个人避让 | P0 | 确认位置、受影响通道和临时避让意愿；无需管理员操作 |
| 障碍生效与绕行 | P0 | 合并本会话有效个人避让与有效公共障碍后请求 ORS；缓存按会话隔离 |
| 报告整理 | P0 | 可复制文字和可打印报告页，供用户人工提交 |
| 配额与异常处理 | P0 | 服务端预算、等待提示、无路可走与外部失败区分 |
| AI 图片识别与 JSON 输出 | P0 | 原生图片输入；JSON Schema 约束字段、类别和不确定性；服务端验证 |
| 异常处理与公共核实 | P1 | 在 Payload Admin 中提供纠错、驳回、解除及有额外证据的公共发布；不阻塞个人核心流程 |
| 地点文字搜索 | P1 | 地址搜索；没有接入时保留地图和预设地点选点 |
| 社区确认与精细个性化 | P2 | 投票、声誉、个人资料、推送和更多通行参数 |
| 全城与自动市政集成 | P2 | 扩大覆盖、实时公共设施接入、获授权后的提交接口 |

比赛范围不包含自建全球路由引擎、室内导航、语音逐向导航、完整账号体系、多租户计费、自动确定道路尺寸或自动判定安全。等时圈接口不是核心闭环依赖。商业定价和付费实例数量单独验证，不写成既有成果。

## 4 核心流程与业务规则

### 4.1 规划与报告流程

打开区域地图 → 选择起点和终点 → 选择通行参数 → 规划路线 → 查看距离、估算时长、数据来源和障碍提示。出行者上传照片后，大模型返回图片质量、障碍类别、可见通行情况、描述、证据和不确定项。用户修正建议，确认地图位置、拍摄时间及当前路线中的受影响通道，提交后获得报告编号。后台保留原始 AI 结果与用户修改，用户修改不冒充模型判断。

### 4.2 个人临时绕行与公共生效流程

用户选择当前路线片段或预设通道 → 自动查看后端生成的避让范围 → 明确确认位置、通道和“为我临时避让” → 后端校验报告归属、AI 结果和用户确认记录 → 按确认的通道生成合理避让范围 → 更新当前会话的个人避让版本 → 用户点击重算 → 合并公共与个人有效避让区域后请求 ORS。返回新路线或“当前条件下未找到路线”，无需管理员参与。结果标注“根据你的报告临时避让，尚未公共核实”。

模型返回不确定、未发现障碍或识别失败时，系统不默认启用避让；用户仍可补充事实、确认通道并明确选择人工填报的个人避让，保留降级标识。缺少位置或通道、几何无效时不能启用。模型不直接生成地图经纬度、避让多边形或全局生效状态。

公共障碍需额外核实后才对所有用户生效。比赛版可通过纠错管理员的补充核实，或经运营者确认的可信维护方数据发布；社区自动交叉核实属于 P2。AI 自评置信度、同一会话重复提交或用户单次确认均不能直接升级为公共已核实。报告可以生成，但须同时显示 AI 状态、核实来源与个人或公共影响范围。

### 4.3 状态与生效规则

| 状态 | 含义 | 地图与路线行为 |
| --- | --- | --- |
| pending 待确认 | 上报已保存，AI 未给出可用障碍结论或用户尚未完成确认 | 不默认避让；可补充信息后明确选择人工填报的个人避让 |
| ai_assessed AI 已分析 | 服务端接受有效的 AI 障碍识别结果 | 完成用户确认和规则校验后可个人避让；不等于公共已核实 |
| verified 公共已核实 | 具有独立核实证据、合法公共几何及有效期 | 有效期内对所有用户纳入避让，显示核实来源 |
| resolved 已解决 | 公共障碍的解除经过额外核实 | 移出公共避让集；保留历史 |
| rejected 已驳回 | 争议复核确认存在错误、滥用或证据不足 | 停止该报告的避让；保留理由 |
| 已过期 | 个人避让或公共核实已超过各自有效期 | 停止对应避让，显示信息过时；不宣称已经恢复通行 |

AI 分析状态、报告生命周期与个人避让开关分别保存。模型结果只能由后端写入；用户可启用或停用自己的个人避让，不能写入 verified。用户取消个人避让不表示公共障碍已解决，也不移除仍有效的公共避让。争议报告的驳回、公共核实与公共解除需受保护的管理权限或已接入的可信来源。

建议个人临时避让从用户确认的观察时间起默认有效 1 小时，公共核实默认有效 24 小时，均为可配置运营值。观察时间不能为未来；过期后续期需要重新确认当前观察时间和通道。更换照片或改变位置、通道后，原确认与个人避让失效，必须重新确认。过期不等于障碍消失。新报告及原图默认仅上报者和纠错管理员可见，公共发布须另外检查证据和图片披露。

- 位置与影响范围分开：上报点由用户确认，通道由当前路线或预设通道选取，避让几何由后端校验生成。图片中的像素坐标不能直接转换为地理避让区域。

- 未核实或未知不能显示为安全。地点可进入不能推导到达它的道路都可通行；普通厕所不能推导为无障碍厕所。

- AI 已分析及人工填报的个人报告可以影响上报者自己的绕行，不改变其他会话路线；公共地图只展示通过发布规则的脱敏信息。

- 多人重复提交同一位置时可标为疑似重复供管理员处理，比赛版不自动合并或自动提高可信度。

## 5 功能需求与验收口径

### 5.1 地图与地点

FR01 区域地图。默认显示配置的演示区域，提供图例和列表视图。地图可定位、缩放和选点；位置权限被拒绝时可手工选起点。验收：手机在不授权定位的情况下仍能完成规划，地图标记与列表一一对应。

FR02 地点状态。显示地点名称、类别、坐标、来源、更新时间，以及可进入、部分可进入、不可进入或未知状态。字段缺失时显示未知，不通过类别或名称推断。验收：包含明确 yes、limited、no 和缺失标签的四条样例均正确展示，分类标签保留原始来源。

FR03 起终点与参数。P0 支持地图选点与预设地点，显示当前 wheelchair 模式和实际使用的限制参数。坡度用百分比，路缘高度和宽度用米；示例数值不是医学建议。验收：起终点可交换、可更换，坐标超出区域会给出可执行提示。

### 5.2 路线与障碍处理

FR04 路线结果。显示路线、距离、估算时长、计算时间、障碍版本及数据限制；明确为基于当前数据的候选路线。只有点击规划、重算或修改确认后的参数才发起计算。验收：拖动地图、切换面板、重绘页面不增加 Directions 调用。

FR05 上报障碍。必须提供照片、地图位置、类别、描述和拍摄时间。照片上传后触发 AI 分析，用户可修改建议并选择当前路线片段或预设通道。验收：无效文件、位置缺失和描述缺失不能提交；正常提交持久化并返回编号，原始 AI 输出与用户修改分别保留。

FR06 用户确认与生效。用户确认观察位置、时间、受影响通道及个人临时避让意愿，后端校验后启用个人避让，不等待管理员。用户仅能操作自己的报告；公共核实和纠错另行鉴权。验收：无管理员登录仍能完成个人绕行；伪造 AI 状态、访问他人报告或直接写入公共已核实状态均被拒绝；并发修改不能无提示覆盖。

FR07 障碍绕行。后台合并本区域全部当前有效公共障碍与本会话已确认的有效个人避让。规划前后保持起终点和通行参数一致。验收：无需管理员即可获得个人绕行建议，其他会话的相同请求不采用该个人障碍；新路线不穿越有效避让区域，超出覆盖或无路线时明确说明，不擅自放宽条件。

FR08 版本与重算提示。公共障碍与个人避让分别维护版本；个人启用、停用、修改或过期仅影响所属会话，公共变更影响所有相关会话。已有路线应在 10 秒内提示对应变更；缓存和进行中的请求按会话及有效避让集隔离。验收：A 会话的个人结果不被 B 会话读取，旧请求不能覆盖较新结果。

### 5.3 照片识别与报告

FR09 AI 图片识别与结构化输出。P0 默认使用 glm-4.6v 的原生图片输入与工具参数 Schema，返回图片质量、是否可见障碍、类别、画面内通道状态、描述、证据和不确定项；后端执行完整结构与语义校验，不要求供应商提供视觉模型原生严格 Schema 保证。后端验证结构及字段间逻辑，用户可修正；图片模糊或证据不足时允许 unknown 或 null。不从照片推断精确宽度、坡度、地理多边形或全局通行结论。验收：合法结果被保存，结构错误、拒绝识别和超时进入明确降级状态；用户仍可人工填报并明确确认个人避让。[S22][S23]

FR10 报告页。包含编号、照片、位置、类别、事实描述、发现时间、AI 分析状态、用户确认时间、个人或公共影响范围，以及公共核实来源和时间；提供复制与打印。验收：明确区分 AI 已分析、人工填报和公共已核实，不把个人绕行显示为公共封路，也不出现未实际完成的“已提交市政”或“已修复”。

FR11 异常与等待。分别显示参数错误、定位失败、AI 分析失败、用户确认缺失、无路线、排队、配额耗尽和外部服务故障。重试保留输入，不把 403 全部解释成额度耗尽。验收：每种错误有独立样例；失败不静默启用个人避让或生成公共障碍，人工备用路径仍须明确确认。

### 5.4 部署和演示模式

FR12 访问与隔离。公众扫码打开移动端体验；演示报告和真实报告使用独立实例或隔离区域，并持续标识演示数据。管理员使用 Payload 认证和受保护的 `/admin` 入口，管理账号与公众匿名会话分开；不能靠前端角色切换获得权限。验收：公开二维码不能直接进入管理员会话；直接调用 Payload 数据接口或文件地址不能越权读取私人数据或修改受保护的业务字段。

FR13 数据持久化。图片保存于阿里云 OSS 私有 Bucket，报告、图片元数据、AI 分析、用户确认及个人或公共生效记录保存于 PostgreSQL，不以临时应用目录持久化。验收：重启后记录和授权图片可读，未授权请求不能直接读取 OSS 图片，过期个人避让不会因重启恢复生效。

FR14 请求预算。ORS 和模型调用均由后端发出，分别设置频率及总量或成本预算；同一密钥共享预算。相同照片及分析配置可复用本会话结果，路线复用必须匹配公共与个人上下文。验收：预算超限有明确提示，不因前端重绘重复分析，也不跨会话泄露个人结果。

## 6 页面与交互要求

| 页面 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 地图首页 | 地点、障碍、起终点、路线摘要和图例 | 规划、手工选点、切换列表、重算 |
| 上报页面 | 照片、AI 结果、发现时间、地图位置、受影响通道 | 修正建议、确认通道、选择个人临时避让；无需管理员 |
| 报告详情 | 证据、AI 状态、确认记录、影响范围、来源和有效期 | 启用或停用自己的避让、复制、打印、重算 |
| Payload 管理后台 | 异常与争议报告、私有证据、公共发布证据、修改历史及区域配置 | `/admin` 登录；调用受保护业务命令完成补充核实、纠错、驳回和公共解除；P1，不作为核心流程入口 |
| 部署说明入口 | 区域范围、数据源、使用限制、配置指引 | 进入演示或查看部署步骤 |

移动端主操作始终可见，地图不能成为唯一入口；提供可聚焦的表单、键盘操作和文本结果。颜色之外同时使用图标与文字表示状态。界面、错误提示和报告统一使用英文，内部开发与验收说明用中文，本轮不做语言切换。

## 7 非功能需求

以下数字均为建议验收目标，不是已测得结果或供应商承诺；本轮轻量验收以[统一验收规则](ACCEPTANCE.md)为准，不把20会话压测、30次P95或极端环境矩阵作为门槛。测试环境记录手机型号、网络、区域大小和账号预算；超过第三方配额的请求应按等待规则处理，不纳入正常请求耗时。

| 编号 | 要求 | 可测目标 |
| --- | --- | --- |
| NFR01 | 移动端可用 | 支持 360 像素宽度；无横向溢出；拒绝定位仍可用 |
| NFR02 | 操作反馈 | 点击后 300 毫秒内显示加载或排队状态 |
| NFR03 | 路线响应 | 30 次低负载测试中，未排队路线请求 P95 小于 8 秒；缓存命中小于 1 秒 |
| NFR04 | 状态传播 | 公共或本会话个人避让改变或过期后 10 秒内提醒对应客户端 |
| NFR05 | 一致性 | 路线匹配公共版本、个人版本与有效集；跨会话隔离，不返回已知过时结果 |
| NFR06 | 权限与数据 | 密钥只在服务端；检查报告与分析归属；原图不默认公开，公共发布和纠错鉴权 |
| NFR07 | 容量目标 | 演示支持 20 个浏览会话；路线调用仍受统一分钟预算控制 |
| NFR08 | 可访问交互 | 表单有标签；焦点可见；文字可替代颜色；地图信息有列表表达 |
| NFR09 | 维护与恢复 | 部署说明可复现；完成一次重启验证和数据备份恢复演练 |
| NFR10 | AI 响应与降级 | 建议分析超时 8 秒；超时或拒绝时保留表单并显示人工备用路径 |

## 8 验收场景与完成定义

| 用例 | 触发条件 | 通过标准 |
| --- | --- | --- |
| AC01 正常规划 | 无有效障碍，固定两点和参数 | 得到有效路线；显示来源、时间和限制 |
| AC02 AI 分析与确认 | 返回有效 JSON，用户尚未确认；另测模糊或矛盾输出 | 可查看并修正；不默认启用个人避让或变为公共已核实 |
| AC03 个人障碍绕行 | 用户确认位置与通道并启用个人避让；全程无管理员操作 | 本会话新路线避开区域或明确无路线；另一会话不采用该个人报告 |
| AC04 停用与过期 | 本人停用或个人避让过期；另测公共障碍经核实解除 | 对应版本或有效集更新；停用个人避让不移除仍有效的公共障碍 |
| AC05 无可用路线 | 全部替代通道均不满足条件 | 无可用路线；不暗中移除限制 |
| AC06 上游异常 | 模拟 429、配额 403、鉴权 403、超时 | 错误准确，有限重试，不出现请求风暴 |
| AC07 权限与并发 | A 操作 B 报告；伪造 AI 结果或 verified；直接调用 Payload CRUD 或文件地址；并发修改 | 越权拒绝；管理操作也不能绕过业务命令；状态由后端确定；过期版本冲突 |
| AC08 缓存竞争 | 相同两点的两个会话；个人避让更新；旧 AI 或路线请求晚到 | 私有结果不串用；过时 AI 不覆盖新照片或用户修改；旧路线不标为当前 |
| AC09 持久化 | 创建图片报告并重启应用 | 记录、图片、状态可读 |
| AC10 降级与报告 | AI 不可用、结构无效或未发现障碍；地点字段缺失；打印报告 | 不默认启用；可人工填报并明确确认个人避让；未知保持未知，报告显示降级与影响范围 |

P0 阶段完成定义：P0 功能已通过 Next.js + Payload 应用部署到 Zenith；无管理员参与即可完成实时 AI 识别、结构校验、用户确认和个人绕行；上述适用验收通过且保留证据。README 含启动、配置、区域、数据来源和部署方法；完成一次完整彩排。AI 未接入不能宣称全部 P0 完成，预存分析仅能作为已标识的备用演示。Payload 公共纠错后台属于 P1，未交付时不开放公共报告发布。

完整项目完成还须交付地点文字搜索、公共核实/纠错/驳回/解除/重新核实/重开、后台证据与审计、单区域配置和调用摘要，并通过[统一验收](ACCEPTANCE.md)。匿名身份采用会话 Cookie，刷新保留、关闭浏览器后不承诺找回；报告持久化寿命与会话寿命分别处理。

## 9 团队分工与交付节奏

四包均须完成 P0 与 P1。详细任务和可复制提示词统一见[工作包目录](../work-packages/README.md)，分支、目录所有权及合入 dev 的规则见[协作规则](COLLABORATION.md)。

| 负责人 | 主要工作 | 可检查的交付 |
| --- | --- | --- |
| A 前端：视觉、地图与路线 | Stitch 落地、公众外壳、地图/列表、选点、路线、通道选择、搜索及公共状态传播 | 手机可规划、搜索并理解公共/个人路线变化 |
| B 前端：上报、报告与管理交互 | 上传、分析修正、预览确认、报告复制打印，以及 Payload 自定义管理组件 | 公众闭环和已挂载后台表单可操作 |
| C 后端：数据、AI 与报告 | Payload、迁移、会话、OSS、GLM、报告/管理命令、权限、审计和后台挂载 | 数据及事务正确、权限受控，个人和公共流程可追踪 |
| D 后端：路由、地理与集成部署 | 骨架、ORS/POI/搜索、几何、预算缓存、摘要、Zenith与dev集成 | 真实路由和搜索、公共传播、在线演示及恢复证据 |

D 优先交付骨架和部署探针，C 同步交付数据契约，A/B 准备公共组件和用户流程。先按阶段合入 dev，再继续各包 P1，避免等待整个工作包结束。下表保留原始24/48小时节奏作为排期参考；完整交付以 P0/P1 验收结果为准。

| 阶段 | 24 小时版 | 48 小时版 | 退出条件 |
| --- | --- | --- | --- |
| 部署和验证 | 0–2h | 0–4h | 空壳上线；真实轮椅路线；实测模型图片输入与结构化输出 |
| 骨架集成 | 2–8h | 4–14h | Next.js + Payload 数据层及迁移可用；地图、私有上传、AI 分析、报告保存与用户确认接口互通 |
| 核心闭环 | 8–14h | 14–24h | 无管理员完成个人绕行或明确无路线；跨会话缓存隔离 |
| 体验与增强 | 14–19h | 24–36h | 报告页、AI 降级和限流；48h 增加搜索及 Payload Admin 公共纠错工具 |
| 冻结与彩排 | 19–24h | 36–48h | 权限、重启、手机测试，真实反馈，备用录像 |

120 秒演示建议：0–20 秒说明受阻问题并显示原路线；20–45 秒上传照片并展示模型结构化识别；45–65 秒由观众确认位置和通道、启用个人避让；65–95 秒重算并比较，展示另一会话不受该报告影响；95–110 秒展示报告；110–120 秒说明范围与部署入口。固定起终点和参数，只改变障碍条件，全程不需要管理员审批。
