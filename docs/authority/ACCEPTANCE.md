# AccessLoop 统一验收规则与追踪

版本 1.0，2026-10-17。适用于完整 P0/P1，技术验收由 AI 执行，人工只负责功能和界面。各包具体提示词和点击清单存放在[各自工作包](../work-packages/README.md)。

## 结果与证据

每份技术验收记录须包含所属包、阶段、当前分支、baseDevCommit、headCommit、执行命令/场景与证据。阶段 PR 指向 dev；D 合并后记录 integratedDevCommit，只复验受影响的集成流程。代码或目标基线变化后，旧证据只可复用其仍适用的部分，不能把旧提交通过结论当作新提交通过。

## 阶段验收与整包验收

- 骨架、基础仓储或共享组件按阶段PR交付；技术验收只对PR明确声明的阶段范围判定。尚未进入阶段的P0/P1记为待交付，不把它们算成本阶段失败，也不因此宣称整包完成。
- 最终整包验收必须覆盖全部P0/P1，阶段通过不能替代最终通过。D只将本阶段技术验收通过的变更合入dev；合前验收不要求变更已经合入，合后再记录集成SHA并回归。
- 验收会话只读核查同步状态并固定待验收head，不通过切换分支或merge改变受检代码。需要同步时交开发会话完成，再重新固定证据提交。最终集成验收可以直接在指定dev提交读取和运行检查。

## 验收分工与通过条件

- 开发 Codex 对整包自检；另开一个 Codex 会话复制该包的 AI 技术验收提示词，独立核验。对应提示词和人工清单见[工作包目录](../work-packages/README.md)。
- 验收 AI 不修改产品代码；开发会话修复后，只复验失败及受影响主流程。
- 人工只检查页面功能、界面和文案。AI 准备可访问入口、演示数据及必要测试账号，人工不运行终端、不查数据库、不抓包或审核权限实现。
- 每包分别记录 P0、P1、整体结果，使用“通过/未通过/外部条件阻塞”。真实能力缺失不以桩、录像或备用流程代替通过。
- 构建和全项目真实闭环在同一集成提交上统一验证；其他包可引用可核对证据，不重复调用供应商。
- 保留一个确定性幂等/版本冲突、事务回滚、迟到响应和过期案例；P1 增加一次管理命令一致性和非法配置验证即可，不搭建冗余矩阵。
- 本轮不把原文档建议的20浏览会话、30次P95、覆盖率或完整跨浏览器矩阵作为交付门槛。少量实际耗时如实记录，不宣称完成未执行的性能测量。
